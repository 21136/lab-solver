# Lab-Solver Agent 计划 — 分维度评审清单

供多个 AI 并行评审时，每个 AI 可只负责一节，避免泛泛而谈。

---

## A. 架构与模块边界

- [ ] `modules/` 接口是否足够稳定？`AgentContext` 字段是否会爆炸？
- [ ] Planner 与 Executor 职责是否清晰？有无循环依赖？
- [ ] `sections_config.normalize()` 拆三套结构是否长期可维护？
- [ ] 快速模式 `/api/solve` 与 Agent 路径长期双轨成本？

## B. 产品与合规

- [ ] 免责声明、隐私文案是否足够？
- [ ] 学术诚信风险是否在 UI 有清晰边界？
- [ ] 范文/模版防抄袭 prompt 是否可执行、可测？

## C. 文档与填表

- [ ] 多文档角色 + 合体拆分 + **粘贴题目**（空模板 + 网页作业）是否覆盖本校常见模版？
- [ ] `fill_scope` 五种模式用户是否学得会？能否再简化？
- [ ] PDF 只导出 docx 的用户预期是否管理到位？
- [ ] `fill_lab` 段落边界（`split_idx`）有无 edge case？

## D. LLM / Token

- [ ] 默认 2 次调用是否仍偏多？能否合并 Planner+solve？
- [ ] `prompt_budget` 裁剪是否丢关键约束？
- [ ] deep 模式 4～5 次是否有合并 understand+plan 的空间？
- [ ] 推理模型与 fast 路径切换是否清晰？

## E. 可靠性与工程

- [ ] cancel / retry-step / 单任务锁是否足够？
- [ ] 降级到 `/api/solve` 的触发条件是否合理？
- [ ] schema_version、日志脱敏、打包验证是否应更早？
- [ ] 金样本 3 份是否够？还应测什么？

## F. UI/UX

- [ ] 分节工作台一步学习成本？
- [ ] 首次引导是否必须 Phase3 才做？
- [ ] 思考过程/审稿意见信息架构是否拥挤？

## G. 实施排期

- [ ] Phase 2a/2b 拆分是否合理？有无阻塞依赖写错？
- [ ] MVP 最小集：若只能做 4 周，砍什么？
- [ ] 哪些「升格」项可再降为 Phase4？

---
