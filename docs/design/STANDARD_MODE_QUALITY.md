# 标准模式 — 质量感知强化

**版本**: 2026-06-09  
**状态**: ✅ 已落地  
**范围**: 标准模式（`run_mode=standard`）的质量保障与 UI 说明；不改深度/ReAct 主流程

---

## 1. 问题

用户反馈标准模式「好像没用」「老生成错误答案」。根因并非标准模式没有质量链路，而是：

| 感知问题 | 实际技术事实 |
|----------|--------------|
| 以为标准 = 随便生成一次 | 标准模式同样走 **V4 分阶段流水线**（读题→写代码→内化验证→写报告→图表） |
| 错了也不修 | 校验（`verify_answer`）一直有，但 **自动修复默认仅深度模式开启** |
| 设置里藏太深 | 「校验未通过时自动修复」在高级设置，默认未勾选 |
| Step 2 无说明 | 页面上看不到「含内化验证 / 自动校验」 |

**深度模式多出来的**：执行前的 understand + reflect 审稿，以及默认 auto_remediate（修复前已有差距）。

---

## 2. 标准 vs 深度（用户可见）

| 能力 | 标准模式 | 深度模式 |
|------|----------|----------|
| V4 流水线 + 质量档位 | ✅ | ✅ |
| 内化验证（沙箱试跑代码） | ✅（档位控制） | ✅ |
| 执行后规则校验 | ✅ | ✅ |
| 校验失败自动修复 1 轮 | ✅ **2026-06-08 起默认开** | ✅ 默认开 |
| 执行前 LLM 审稿修订 | ❌ | ✅ |

编程题若仍不满意：设置 → 质量档位选 **稳妥**，或切换 **深度模式**。
